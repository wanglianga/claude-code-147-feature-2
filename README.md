# 云溪山居 · 乡村民宿旺季运营平台

面向乡村民宿旺季（节假日）的一体化运营平台：统一 **官网 / 小程序 / OTA / 电话** 四渠道的房态、价格、入住人数、宠物规则、儿童加床、早餐份数、押金与发票要求；把 **订单 → 保洁 → 布草 → 维修 → 早餐 → 事件 → 差评补偿 → 结算** 放进同一条住宿链路；覆盖 **布草延迟影响入住** 场景（保洁完成但布草车山路堵车未到，房间「待布草」无法交付，平台记录缺口/预计到达/可调拨房间/客人等待时长，管家可下午茶安抚、延迟入住补偿或调拨换房，布草到达后房态自动恢复可入住，补偿计入当日运营成本，多次延迟自动提示安全库存/洗涤供应商/高峰连住调整建议）；旺季结束后按渠道/房型/服务环节复盘利润，并据超卖、布草延迟、早餐投诉、补偿成本自动调整下一轮节假日的可售房量。

## 技术栈

- 前端：React 18 + Vite + Ant Design 5 + ECharts
- 后端：NestJS 10 + TypeORM（含 Swagger 文档 `/api/docs`）
- 数据库：PostgreSQL（开发用 15 验证，Compose 用 16）

## 一键启动（Docker Compose）

```bash
docker compose up --build
```

- 前端：http://localhost:8080
- 后端 API：http://localhost:3000/api （Swagger 文档：http://localhost:3000/api/docs）
- 首次启动自动建表并写入 **2026 国庆旺季（10-01~10-08，"今天"为 10-03）** 演示数据：12 间房、4 渠道、20 张订单、保洁/布草/维修/早餐记录、8 类履约事件、5 条评价与补偿记录、2 条布草缺口（203 房待布草等待中 + 10-02 历史已恢复）。

## 本地开发

```bash
# 1. 数据库（任一方式）
docker compose up -d db                                  # 用 Compose 起 Postgres(5432)
# 或使用本机已有 PostgreSQL，创建 homestay 库后通过 DATABASE_URL 指向它

# 2. 后端（首次启动自动建表+种子数据）
cd server && npm install
DATABASE_URL=postgres://homestay:homestay123@localhost:5432/homestay npm run start:dev

# 3. 前端（Vite 代理 /api → localhost:3000）
cd web && npm install && npm run dev                    # http://localhost:5173
```

## 演示动线（种子数据已埋好完整故事线）

1. **经营看板**：入住率/ADR/RevPAR、渠道收入分布、履约事件分布、差评归因四象限（硬件/服务/超卖/餐食）；**当日运营成本**卡（保洁/布草洗涤/早餐/维修/补偿分项与合计，含布草延迟补偿明细）。
2. **房态日历**：房间×日期占用与价格；下方库存表可见 10-01 庭院双床房、10-04 山景大床房两处**超卖**红色告警；203 房显示紫色「待布草」。
3. **订单管理**：新建订单会统一校验宠物/加床/人数规则与库存（OTA 可强制下单并触发超卖事件）；订单详情抽屉含 **链路事件 / 保洁 / 评价补偿 / 结算明细** 五个页签。可现场操作：入住 → 临时加人（早餐费自动重算）→ 延迟退房（自动生成事件+保洁任务）。**待布草房间的订单无法办理入住**（提示先调拨换房或等布草送达）。
4. **保洁与布草**：「智能排班」按下一单入住时间、脏污程度、维修冲突、布草库存自动派单（301 房有空调维修告警）；完成打扫扣减布草；送洗签收超时 2 小时自动记布草延迟事件。**布草延迟影响入住**：203 房保洁已完成但布草车因山路堵车未到，缺口表记录缺口布草、预计到达、客人等待时长；管家可 **下午茶安抚（¥68）/ 延迟入住补偿 / 调拨换房**（自动列出可入住且无冲突的候选房，同房型优先）；在「送洗配送」签收堵车的床单后，**待布草房间自动恢复可入住**，关联事件自动关闭。顶部 Banner 在布草延迟多次出现时给出 **增加安全库存 / 调整洗涤供应商 / 限制高峰连住订单** 建议。
5. **早餐备餐**：按在住人数与忌口（不吃辣/素食/海鲜过敏）自动汇总需求；确认备餐量不足即生成早餐供应不足事件。
6. **事件与差评**：差评（≤3 分）自动进入链路；对差评发放现金/退款/补偿券（自动生券码），补偿后差评事件自动关闭；补偿券可核销。布草延迟的下午茶/延迟入住补偿同样进入补偿记录。
7. **结算中心**：每笔订单的房费、加床、早餐、宠物费、渠道佣金（OTA 15%）、赔付补偿、押金扣留/退还、净收入逐行列清。
8. **旺季复盘**：分渠道/分房型利润表、服务环节收入 vs 成本、问题自动归类（价格策略问题/履约能力问题/个别客诉）；最下方给出下一轮节假日各房型**建议可售房量**（本例中山景大床房因超卖+布草+早餐+补偿综合下调 3→2），选择日期区间后「应用到下一轮节假日」即写入库存。

## 验证方式（实际执行过的验证）

本仓库交付前在 Linux + PostgreSQL 15 + Node 22 环境实际执行：

```bash

cd server && npx tsc -p tsconfig.build.json

# 端到端 API 验证（65 项断言全部通过）
python3 scripts/verify.py
```

`scripts/verify.py` 覆盖：登录鉴权、禁宠/加床/人数规则拒绝、库存不足 409、OTA 强制下单触发超卖事件、临时加人费用重算、延迟退房事件、退房生成保洁任务、智能排班（含维修冲突告警）、保洁完成扣减布草、布草延迟事件、**布草延迟影响入住（待布草房间不可入住、缺口记录含预计到达与等待时长、可调拨房间筛选、下午茶/延迟入住补偿计入当日运营成本、调拨换房后订单房间变更并可入住、布草到达后缺口自动关闭且房态自动转可入住、多次延迟产出安全库存/供应商/限连住三类建议）**、早餐需求汇总与不足事件、差评自动入链、补偿券发放与核销、结算净额勾稽、OTA 15% 佣金校验、复盘三分类、调价建议与库存应用。

前端通过 `npm run build` 构建，并以 `vite preview` 验证页面、静态资源与 `/api` 代理连通（登录接口 201、布草缺口接口 200）。
