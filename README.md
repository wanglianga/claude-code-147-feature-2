# 云溪山居 · 乡村民宿旺季运营平台

面向乡村民宿旺季（节假日）的一体化运营平台：统一 **官网 / 小程序 / OTA / 电话** 四渠道的房态、价格、入住人数、宠物规则、儿童加床、早餐份数、押金与发票要求；把 **订单 → 保洁 → 布草 → 维修 → 早餐 → 事件 → 差评补偿 → 结算** 放进同一条住宿链路；旺季结束后按渠道/房型/服务环节复盘利润，并据超卖、布草延迟、早餐投诉、补偿成本自动调整下一轮节假日的可售房量。

## 技术栈

- 前端：React 18 + Vite + Ant Design 5 + ECharts
- 后端：NestJS 10 + TypeORM（含 Swagger 文档 `/api/docs`）
- 数据库：PostgreSQL（开发用 15 验证，Compose 用 16）

## 一键启动（Docker Compose）

```bash
docker compose up --build
```

- 前端：http://localhost:8080
- 后端 API：http://localhost:3000/api （Swagger 文档：http://localhost:3000/api/docs）
- 首次启动自动建表并写入 **2026 国庆旺季（10-01~10-08，"今天"为 10-03）** 演示数据：12 间房、4 渠道、20 张订单、保洁/布草/维修/早餐记录、8 类履约事件、5 条评价与补偿记录。

## 本地开发

```bash
# 1. 数据库（任一方式）
docker compose up -d db                                  # 用 Compose 起 Postgres(5432)
# 或使用本机已有 PostgreSQL，创建 homestay 库后通过 DATABASE_URL 指向它

# 2. 后端（首次启动自动建表+种子数据）
cd server && npm install
DATABASE_URL=postgres://homestay:homestay123@localhost:5432/homestay npm run start:dev

# 3. 前端（Vite 代理 /api → localhost:3000）
cd web && npm install && npm run dev                    # http://localhost:5173
```

## 演示动线（种子数据已埋好完整故事线）

1. **经营看板**：入住率/ADR/RevPAR、渠道收入分布、履约事件分布、差评归因四象限（硬件/服务/超卖/餐食）。
2. **房态日历**：房间×日期占用与价格；下方库存表可见 10-01 庭院双床房、10-04 山景大床房两处**超卖**红色告警。
3. **订单管理**：新建订单会统一校验宠物/加床/人数规则与库存（OTA 可强制下单并触发超卖事件）；订单详情抽屉含 **链路事件 / 保洁 / 评价补偿 / 结算明细** 五个页签。可现场操作：入住 → 临时加人（早餐费自动重算）→ 延迟退房（自动生成事件+保洁任务）。
4. **保洁与布草**：「智能排班」按下一单入住时间、脏污程度、维修冲突、布草库存自动派单（301 房有空调维修告警）；完成打扫扣减布草，**布草车未到/库存不足时房间自动转「待布草」**；送洗签收超时 2 小时自动记布草延迟事件。
   - **布草堵车·延迟入住专线**：10-03 当天 103 房保洁刚完成，但布草车因午后山路堵车未到（系统按当前时间锚定为半小时前发生、预计 2.5 小时后到达，任何时区打开都是进行中现场），沈女士一家提前到店无法按时入住。页面顶部红色告警与「待布草房间」表记录：**布草缺口（床单 1 套）、布草预计到达、可调拨房间（自动匹配同房型当晚空房 101）、客人等待时间**；此状态下订单办理入住会被 **409 拦截**。
   - **管家待客补偿**：可对等待客人发放**免费下午茶**、**延迟入住补偿**，或一键**换房调拨**（订单直接调至 101，原房继续等布草）；补偿费用实时进入**当日运营成本**卡片（下午茶/换房/延迟入住分项）。
   - **到达自动恢复**：在「送洗配送」签收堵车布草车后，待布草房**自动从「待布草」转为可入住（已验收）**、布草延迟事件自动关闭并写入客人实际等待时长，随后即可正常办理入住。
   - **多次延迟的平台提示**：旺季已出现 2 次布草延迟（延迟率 40%）时，页面下方自动给出三类处置建议并可一键落地：**增加安全库存**（按保有量 25% 上调，库存触及安全线变红预警）、**调整洗涤供应商**（记录备用厂与延时赔付条款）、**限制高峰连住订单**（高峰区间每房型保留 1 间布草周转缓冲房）。
5. **早餐备餐**：按在住人数与忌口（不吃辣/素食/海鲜过敏）自动汇总需求；确认备餐量不足即生成早餐供应不足事件。
6. **事件与差评**：差评（≤3 分）自动进入链路；对差评发放现金/退款/补偿券（自动生券码），补偿后差评事件自动关闭；补偿券可核销。
7. **结算中心**：每笔订单的房费、加床、早餐、宠物费、渠道佣金（OTA 15%）、赔付补偿、押金扣留/退还、净收入逐行列清。
8. **旺季复盘**：分渠道/分房型利润表、服务环节收入 vs 成本、问题自动归类（价格策略问题/履约能力问题/个别客诉）；最下方给出下一轮节假日各房型**建议可售房量**（本例中山景大床房因超卖+布草+早餐+补偿综合下调 3→2），选择日期区间后「应用到下一轮节假日」即写入库存。

## 验证方式（实际执行过的验证）

本仓库交付前在 Linux + PostgreSQL 15 + Node 22 环境实际执行：

```bash
# 后端编译
cd server && npx tsc -p tsconfig.build.json

# 端到端 API 验证（70 项断言全部通过）
python3 scripts/verify.py
```

`scripts/verify.py` 覆盖：登录鉴权、禁宠/加床/人数规则拒绝、库存不足 409、OTA 强制下单触发超卖事件、临时加人费用重算、延迟退房事件、退房生成保洁任务、智能排班（含维修冲突告警）、保洁完成扣减布草、**布草库存不足保洁完成自动转待布草**、布草延迟事件、早餐需求汇总与不足事件、差评自动入链、补偿券发放与核销、结算净额勾稽、OTA 15% 佣金校验、复盘三分类、调价建议与库存应用；

新增 **布草堵车·待布草专线 25 项断言**：缺口/ETA/等待时间/可调拨房间记录、待布草入住 409 拦截、下午茶与延迟入住补偿、换房调拨（订单换房、原房继续等布草）、补偿费用进入当日运营成本（按类型拆分）、签收后房态自动转可入住且事件自动关闭、布草到达后可入住、多次延迟触发增加安全库存/调整供应商/限制高峰连住三类建议及动作落地（安全库存上调并预警、供应商记录、高峰库存下调）。

前端通过 `npm run build` 构建，并以 `vite preview` 验证页面、静态资源与 `/api` 代理连通（登录接口 200）。
